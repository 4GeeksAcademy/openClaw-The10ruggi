# Consultar mentorías de 4Geeks

Reconoce estas peticiones como consultas de esta skill: «¿Qué mentores hay disponibles?» lista el directorio público, sin prometer disponibilidad de agenda; «¿Cuántas mentorías tengo?» consulta sesiones propias y usa el conteo devuelto; «¿Cuándo tengo mi próxima mentoría?» identifica una próxima solo si los campos devueltos permiten hacerlo; «Comprueba si aparece mi reserva» vuelve a consultar sesiones propias y comunica solo si la respuesta actual la incluye. Si los datos no permiten responder, dilo expresamente en lugar de deducirlo.

1. Para listar/buscar mentores ejecuta `scripts/get_mentorships.py mentors` mediante `exec` con `host="gateway"`. Para buscar por nombre o texto de especialidad disponible, añade `--query "texto"`. El helper solo llama `GET https://breathecode.herokuapp.com/v1/mentorship/public/mentor` y normaliza acentos para la búsqueda. Una lista vacía es resultado válido; los HTTP/JSON/estructura/timeout fallidos son errores, no una lista vacía.
2. Para ver o comprobar sesiones propias ejecuta `scripts/get_mentorships.py sessions` en Gateway. Solo consulta `GET https://breathecode.herokuapp.com/v1/mentorship/user/me/session`. Si `count=0`, responde que no hay mentorías registradas actualmente. Si hay filas, presenta solo valores presentes: mentor, servicio, fecha/hora devueltas y estado original. Destaca como próxima únicamente una fila con `status=PENDING` y `starts_at` válido en el futuro; no deduzcas una fecha futura de `started_at`, `ended_at` ni de un estado por sí solos. Si no hay datos suficientes para ordenar/identificar próximas, di que la respuesta no permite determinarlo.
3. Ambos comandos reutilizan `TOKEN_4GEEKS` del entorno Gateway y el patrón HTTPS/`Authorization: Token <token>` existente; no implementes ni busques otra autenticación. El helper aplica timeout de 20 s, rechaza redirecciones y limita cada cuerpo a 64 KiB. Nunca muestres, guardes ni registres el token, encabezados, cuerpo completo ni detalles de excepciones. No hagas más de la lectura necesaria para la petición actual; no reintentes automáticamente.
4. Para cada mentor muestra solo el nombre real si viene en `user.first_name`/`user.last_name`, la especialidad/servicio únicamente si la respuesta incluye esos campos, y `mentor_slug` solo si aparece explícitamente. El endpoint puede devolver entradas sin slug ni servicios: no los deduzcas ni inventes nombres o especialidades. Para consulta por nombre/especialidad, presenta solo coincidencias; si no hay coincidencias, dilo claramente y ofrece volver a listar. No llames «disponible para reservar» a un mentor salvo que la API aporte ese dato.
5. Para una petición de reserva, primero busca el mentor y confirma su slug con datos de API. El único flujo documentado es página web `/mentor/{mentor_slug}` o `/mentor/{mentor_slug}/service/{service_slug}` (este último solo cuando ambos slugs vienen en datos reales), con token en el parámetro `token`; Calendly es donde el estudiante comprueba horarios y confirma. No se ha verificado disponibilidad mediante API. Nunca construyas, muestres, registres ni envíes un enlace con el token, ni intentes abrirlo en un navegador: en esta skill no existe una apertura privada verificada que proteja el token de la URL, historial, registros o vista de navegador. Si no hay una vía segura disponible, explica la limitación y comparte solo el nombre/slug del mentor disponible de forma segura; no afirmes que preparaste o completaste una reserva. Indica que la fecha/hora pedida debe confirmarse en Calendly. No hagas POST/PUT/PATCH/DELETE ni canceles/modifiques citas.
6. Tras que el usuario diga que reservó y pida comprobarlo, vuelve a consultar `sessions` y describe lo que la API devuelve ahora. Si la lista sigue vacía, di que la API todavía no muestra la reserva; no concluyas que se canceló o que no existe en Calendly. Nunca presentes una reserva como confirmada sin evidencia en la respuesta.
7. En Telegram usa español, texto breve en líneas y viñetas, sin tablas. Ejemplo de sesión vacía: `📅 No tienes mentorías registradas actualmente.` Para sesiones existentes, muestra `📅 TUS PRÓXIMAS MENTORÍAS` solo si las fechas/estados permiten identificar próximas; para cada sesión incluye `🧑‍🏫 Mentor`, `📆 Fecha`, `🕒 Hora` y `📌 Estado` solo cuando el API devuelva esos datos. Conserva exactamente el estado original. Para mentorías no futuras o sin fecha suficiente usa `📋 TUS MENTORÍAS` y no las llames próximas. Informa errores de HTTP, conexión, JSON o estructura brevemente, sin confundirlos con lista vacía.
8. Al terminar verifica que nombres, especialidades, slugs, estados y fechas provienen de campos API, que la respuesta vacía se distingue de errores y que ningún texto o enlace contiene el token. Esta skill es de consulta y orientación segura; no gestiona cambios de reservas ni integra servicios externos.
